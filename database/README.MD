# База данных

## Описание

Для проекта разработана реляционная база данных PostgreSQL 17, предназначенная для хранения и обработки информации об обслуживании автомобилей в автосервисе.

База данных реализована на основе ранее разработанной логической модели и связана с REST API проекта.

## Основные сущности

В базе данных реализованы следующие таблицы:

- `customers` — клиенты;
- `vehicles` — автомобили клиентов;
- `service_requests` — заявки на обслуживание;
- `service_orders` — заказ-наряды;
- `diagnostics` — результаты диагностики;
- `works` — перечень выполняемых работ;
- `parts` — запчасти и их остатки на складе;
- `order_works` — работы, включённые в заказ-наряд;
- `order_parts` — запчасти, использованные в заказ-наряде.

## Связи между таблицами

Основные связи:

- один клиент может иметь несколько автомобилей;
- один автомобиль может иметь несколько заявок на обслуживание;
- одной заявке соответствует один заказ-наряд;
- один заказ-наряд может содержать несколько диагностических записей;
- один заказ-наряд может включать несколько работ;
- один заказ-наряд может включать несколько запчастей.

Для реализации связей «многие ко многим» используются таблицы `order_works` и `order_parts`.

## Ограничения целостности

В БД реализованы:

- первичные ключи (`PRIMARY KEY`);
- внешние ключи (`FOREIGN KEY`);
- уникальность VIN автомобиля;
- уникальность артикула запчасти;
- проверки стоимости работ и запчастей;
- проверка количества запчастей на складе;
- проверка пробега автомобиля;
- ограничения допустимых статусов заявок и заказ-нарядов.

## Индексы

Для ускорения поиска созданы индексы по:

- клиентам автомобилей;
- автомобилям заявок;
- дате обслуживания;
- статусам заявок;
- статусам заказ-нарядов;
- диагностике;
- связанным работам и запчастям.

## Файл схемы

SQL-скрипт создания структуры базы данных находится в файле:

`schema.sql`

Скрипт рассчитан на PostgreSQL 17.
