# Обзор проекта

## 1. Заказчик

АО «Рольф» — сеть сервисных центров, оказывающая услуги 
по продаже автомобилей, а также их техническому обслуживанию и ремонту.

Ниже представлена организационная структура компании (диаграмма построена в ПО Sila Union):

![Орг структура](img/org_structure.png)

## 2. Название системы

AutoService Management System (ASMS)

## 3. Проблема

Процесс технического обслуживания автомобилей включает большое
количество операций, выполняемых различными сотрудниками сервисного
центра.

Использование разрозненных инструментов и выполнение части операций
вручную может приводить к дублированию данных, увеличению времени
обслуживания, ошибкам при обработке информации и сложностям контроля
текущего состояния заказа.

## 4. Цель проекта

Спроектировать информационную систему, обеспечивающую управление
основными этапами процесса технического обслуживания автомобилей.

## 5. Задачи проекта

В рамках проекта необходимо:

1. Исследовать предметную область.
2. Проанализировать текущий бизнес-процесс.
3. Выявить проблемы и узкие места.
4. Разработать целевую модель процесса.
5. Сформировать функциональные и нефункциональные требования.
6. Спроектировать информационную систему.
7. Разработать модель данных.
8. Спроектировать REST API.
9. Создать прототип пользовательского интерфейса.
10. Реализовать демонстрационный backend.
11. Подготовить тестовые сценарии.

## 6. В рамках проекта

В систему входят:

- клиенты;
- автомобили;
- заявки;
- запись на обслуживание;
- заказ-наряды;
- диагностика;
- работы;
- запчасти;
- чек-листы;
- согласование дополнительных работ;
- уведомления;
- история обслуживания.

## 7. За рамками проекта

В проект не входят:

- бухгалтерский учёт;
- управление заработной платой;
- кадровый учёт;
- полноценная ERP-система;
- управление закупками;
- реальная интеграция с 1С;
- мобильное приложение;
- онлайн-эквайринг.

## 8. Ожидаемый результат

Результатом проекта должна стать документация и демонстрационный
прототип информационной системы, включающие бизнес-анализ,
системные требования, модели процессов, архитектуру, модель данных,
API, пользовательский прототип и тестовые сценарии.
