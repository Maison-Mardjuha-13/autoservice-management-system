# Архитектура системы

## 1. Общая информация

AutoService Management System представляет собой информационную систему,
построенную по трёхуровневой архитектуре.

Основными уровнями являются:

- пользовательский интерфейс;
- серверная часть;
- база данных.

Также система предусматривает взаимодействие с внешними сервисами.

---

## 2. Компоненты системы

### Пользовательский интерфейс

Web UI предоставляет доступ к функциям системы для клиентов
и сотрудников сервисного центра.

Пользователи взаимодействуют с системой через браузер.

---

### Backend API

Backend API реализует основную бизнес-логику системы.

Основные модули:

- Auth — управление пользователями и ролями;
- Customers — управление клиентами;
- Vehicles — управление автомобилями;
- Orders — управление заказами-нарядами;
- Service — диагностика и выполнение работ;
- Parts — управление запчастями;
- Notify — отправка уведомлений;
- Reports — формирование отчётности.

---

### База данных

PostgreSQL используется для хранения информации о:

- клиентах;
- автомобилях;
- заявках;
- заказах;
- работах;
- диагностике;
- запчастях;
- уведомлениях.

---

### ERP System

Внешняя ERP-система используется для получения информации
о наличии необходимых запчастей.

В рамках PET-проекта интеграция моделируется через REST API.

---

### Notification Service

Сервис уведомлений используется для отправки клиентам сообщений
о подтверждении записи, согласовании дополнительных работ
и готовности автомобиля.

---

## 3. Взаимодействие компонентов

Пользователь отправляет запрос через Web UI.

Web UI передаёт запрос в Backend API.

Backend API выполняет бизнес-логику, обращается к базе данных
и при необходимости взаимодействует с внешними сервисами.

После обработки Backend API возвращает результат пользователю
через Web UI.

---

## 4. Тип архитектуры

Для демонстрационного проекта используется модульная монолитная
архитектура.

Такой подход позволяет разделить бизнес-логику на независимые
модули, сохраняя единое приложение и упрощая дальнейшую разработку.
