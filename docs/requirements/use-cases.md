# Use Cases

## UC-001 — Создание заявки

**Актор:** Сервисный консультант

**Цель:** Создать заявку клиента на техническое обслуживание автомобиля.

**Предусловия:**
- клиент зарегистрирован в системе;
- автомобиль зарегистрирован и связан с клиентом.

**Основной сценарий:**

1. Сотрудник открывает форму создания заявки.
2. Выбирает клиента.
3. Выбирает автомобиль.
4. Выбирает необходимую услугу.
5. Указывает желаемую дату и время.
6. Добавляет комментарий клиента.
7. Система проверяет корректность введённых данных.
8. Система создаёт заявку.
9. Система присваивает заявке статус `NEW`.
10. Система отображает созданную заявку.

**Альтернативные сценарии:**

- Если обязательные данные не заполнены, система отображает сообщение об ошибке.
- Если автомобиль не найден, сотрудник должен зарегистрировать его перед созданием заявки.

**Результат:**

Заявка создана и доступна сотрудникам сервисного центра.

**Связанные требования:** FR-003, FR-001, FR-002, BR-003

## UC-002 — Запись на техническое обслуживание

**Актор:** Сервисный консультант

**Цель:** Записать автомобиль клиента на обслуживание на доступное время.

**Предусловия:**
- заявка существует;
- автомобиль и клиент указаны в заявке.

**Основной сценарий:**

1. Сотрудник открывает заявку.
2. Выбирает дату обслуживания.
3. Система отображает доступные временные интервалы.
4. Сотрудник выбирает подходящий интервал.
5. Система проверяет доступность сервисного поста.
6. Система создаёт запись.
7. Система изменяет статус заявки на `CONFIRMED`.
8. Система сохраняет дату и время обслуживания.
9. Система формирует уведомление клиенту.

**Альтернативные сценарии:**

- Если выбранное время уже занято, система сообщает об этом.
- Сотрудник выбирает другой доступный интервал.

**Результат:**

Автомобиль записан на техническое обслуживание.

**Связанные требования:** FR-004, FR-012, BR-004, BR-005

## UC-003 — Создание заказа-наряда

**Актор:** Мастер-приёмщик

**Цель:** Создать заказ-наряд для выполнения работ по автомобилю.

**Предусловия:**
- заявка подтверждена;
- автомобиль должен быть принят в сервис.

**Основной сценарий:**

1. Мастер-приёмщик открывает подтверждённую заявку.
2. Система отображает данные клиента и автомобиля.
3. Мастер-приёмщик создаёт заказ-наряд.
4. Система присваивает заказу уникальный идентификатор.
5. Мастер-приёмщик добавляет планируемые работы.
6. Система рассчитывает предварительную стоимость.
7. Система сохраняет заказ-наряд.
8. Система связывает заказ с клиентом и автомобилем.
9. Заказ получает статус `WAITING_FOR_SERVICE`.

**Альтернативные сценарии:**

- Если заявка не подтверждена, создание заказа-наряда невозможно.
- Если обязательные данные отсутствуют, система сообщает об ошибке.

**Результат:**

Создан электронный заказ-наряд.

**Связанные требования:** FR-005, FR-007, BR-016, BR-017

## UC-004 — Проведение диагностики

**Актор:** Автомеханик

**Цель:** Провести диагностику автомобиля и зафиксировать её результаты.

**Предусловия:**
- автомобиль принят в сервис;
- существует активный заказ-наряд.

**Основной сценарий:**

1. Автомеханик открывает заказ-наряд.
2. Система отображает информацию об автомобиле.
3. Автомеханик выполняет диагностику.
4. Автомеханик фиксирует результаты диагностики.
5. Автомеханик указывает выявленные неисправности.
6. Система сохраняет результаты.
7. Система изменяет статус заказа на `DIAGNOSTICS`.
8. При необходимости формируется перечень дополнительных работ.

**Альтернативные сценарии:**

- Если неисправности не обнаружены, дополнительные работы не формируются.
- Если данные диагностики заполнены некорректно, система не позволяет завершить операцию.

**Результат:**

Результаты диагностики сохранены в заказе-наряде.

**Связанные требования:** FR-006, BR-020, BR-021

## UC-005 — Проверка наличия запчастей

**Актор:** Мастер-приёмщик

**Цель:** Определить наличие необходимых запчастей для выполнения работ.

**Предусловия:**
- существует заказ-наряд;
- в заказе определён перечень необходимых работ и запчастей.

**Основной сценарий:**

1. Мастер-приёмщик открывает заказ-наряд.
2. Система определяет необходимые запчасти.
3. Система выполняет проверку складских остатков.
4. Система отображает наличие каждой запчасти.
5. Доступные запчасти могут быть зарезервированы.
6. Система сохраняет результат проверки.
7. Мастер-приёмщик принимает решение о дальнейшем выполнении работ.

**Альтернативные сценарии:**

- Если все запчасти доступны, работы могут быть запланированы.
- Если запчасти отсутствуют, система сообщает об их отсутствии.
- При необходимости сотрудник может ожидать поставку недостающей запчасти.

**Результат:**

Сотрудник знает, какие запчасти доступны для выполнения заказа.

**Связанные требования:** FR-008, BR-006, BR-012, BR-013, BR-014

## UC-006 — Согласование дополнительных работ

**Актор:** Клиент

**Цель:** Получить согласие клиента на выполнение дополнительных работ.

**Предусловия:**
- проведена диагностика;
- выявлены дополнительные работы;
- дополнительные работы добавлены в заказ-наряд.

**Основной сценарий:**

1. Система формирует перечень дополнительных работ.
2. Система рассчитывает их стоимость.
3. Клиент получает информацию о дополнительных работах.
4. Клиент просматривает перечень работ и стоимость.
5. Клиент подтверждает выполнение работ.
6. Система фиксирует согласие клиента.
7. Система добавляет согласованные работы в заказ-наряд.
8. Система пересчитывает итоговую стоимость.
9. Заказ возвращается в процесс выполнения.

**Альтернативный сценарий:**

1. Клиент отказывается от дополнительных работ.
2. Система фиксирует отказ.
3. Дополнительные работы не выполняются.
4. Основные работы продолжаются.

**Результат:**

Получено и зафиксировано решение клиента.

**Связанные требования:** FR-009, BR-007, BR-008, BR-024, BR-025

## UC-007 — Завершение обслуживания

**Актор:** Мастер-приёмщик

**Цель:** Завершить обслуживание и подготовить автомобиль к выдаче клиенту.

**Предусловия:**
- все обязательные работы выполнены;
- необходимые дополнительные работы согласованы или отклонены;
- контроль качества выполнен успешно.

**Основной сценарий:**

1. Мастер-приёмщик открывает заказ-наряд.
2. Система проверяет выполнение обязательных работ.
3. Система проверяет результат контроля качества.
4. Система формирует итоговую стоимость.
5. Система формирует итоговую информацию о выполненных работах.
6. Заказ переводится в статус `READY_FOR_PICKUP`.
7. Система уведомляет клиента о готовности автомобиля.
8. Клиент получает автомобиль.
9. Сотрудник фиксирует факт выдачи.
10. Система переводит заказ в статус `COMPLETED`.

**Альтернативные сценарии:**

- Если обязательная работа не выполнена, заказ нельзя завершить.
- Если контроль качества не пройден, автомобиль не может быть выдан.
- Если выявлены дополнительные недостатки, автомобиль возвращается на доработку.

**Результат:**

Автомобиль выдан клиенту, а заказ-наряд закрыт.

**Связанные требования:** FR-010, FR-011, BR-009, BR-010, BR-011

## UC-008 — Просмотр истории обслуживания

**Актор:** Клиент

**Цель:** Просмотреть историю технического обслуживания автомобиля.

**Предусловия:**
- клиент авторизован;
- автомобиль зарегистрирован в системе.

**Основной сценарий:**

1. Клиент открывает список своих автомобилей.
2. Выбирает необходимый автомобиль.
3. Система отображает информацию об автомобиле.
4. Клиент открывает историю обслуживания.
5. Система отображает список завершённых заказов.
6. Клиент выбирает необходимый заказ.
7. Система отображает:
   - дату обслуживания;
   - выполненные работы;
   - использованные запчасти;
   - итоговую стоимость.

**Альтернативный сценарий:**

Если история обслуживания отсутствует, система отображает сообщение
о том, что ранее завершённых заказов нет.

**Результат:**

Клиент получает информацию о предыдущем техническом обслуживании.

**Связанные требования:** FR-013, BR-004
