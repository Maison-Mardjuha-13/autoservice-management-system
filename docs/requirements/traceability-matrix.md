# Матрица трассируемости требований

## 1. Назначение

Матрица трассируемости связывает требования системы с вариантами
использования, бизнес-правилами и REST API.

Она позволяет проверить, что каждое функциональное требование
имеет соответствующий сценарий использования и технический интерфейс.

## 4. Трассировка бизнес-правил

| ID | Бизнес-правило | Связанные требования |
|---|---|---|
| BR-001 | Клиент должен существовать в системе для выполнения операций, связанных с его обслуживанием | FR-001, FR-002 |
| BR-002 | Автомобиль должен быть связан с существующим клиентом | FR-003, FR-004 |
| BR-003 | Заявка должна быть связана с существующим автомобилем, а выбранное время обслуживания должно быть доступно | FR-005, FR-006, FR-007 |
| BR-004 | Заказ-наряд создаётся на основании существующей заявки | FR-008, FR-009 |
| BR-005 | Изменение статуса заказа выполняется только при допустимом переходе между состояниями | FR-010, FR-018 |
| BR-006 | Результаты диагностики сохраняются в рамках конкретного заказа-наряда | FR-011, FR-012 |
| BR-007 | Работы добавляются непосредственно в заказ-наряд | FR-013, FR-014 |
| BR-008 | Перед использованием запчасти необходимо проверить её наличие на складе | FR-015, FR-016, FR-017 |
| BR-009 | Передача автомобиля клиенту выполняется после завершения обслуживания | FR-018 |

## 7. Заключение

Матрица трассируемости обеспечивает связь между требованиями,
бизнес-правилами, вариантами использования и REST API системы.

Это позволяет контролировать соответствие проектируемого API
исходным требованиям и использовать матрицу в дальнейшем
для подготовки тестовых сценариев.
