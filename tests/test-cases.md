# Тест-кейсы

## 1. Назначение

Тест-кейсы предназначены для проверки функциональных требований системы
управления техническим обслуживанием автомобилей.

---

## 2. Основные тест-кейсы

| ID | Название | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|---|
| TC-001 | Создание клиента | Пользователь находится в системе | 1. Открыть создание клиента. 2. Ввести ФИО, телефон и email. 3. Сохранить | Клиент создан и получил уникальный идентификатор |
| TC-002 | Получение данных клиента | Клиент существует | 1. Указать customerId. 2. Отправить GET-запрос | Система возвращает данные клиента |
| TC-003 | Добавление автомобиля | Клиент существует | 1. Указать данные автомобиля. 2. Указать customerId. 3. Сохранить | Автомобиль создан и связан с клиентом |
| TC-004 | Получение данных автомобиля | Автомобиль существует | 1. Указать vehicleId. 2. Отправить GET-запрос | Система возвращает данные автомобиля |
| TC-005 | Создание заявки | Автомобиль существует, выбранное время свободно | 1. Выбрать автомобиль. 2. Указать дату и время. 3. Добавить комментарий. 4. Создать заявку | Заявка создана со статусом NEW |
| TC-006 | Получение списка заявок | В системе существуют заявки | 1. Отправить GET /requests | Система возвращает список заявок |
| TC-007 | Получение заявки | Заявка существует | 1. Указать requestId. 2. Отправить GET-запрос | Система возвращает данные заявки |
| TC-008 | Создание заказа-наряда | Существует заявка | 1. Указать requestId. 2. Указать employeeId. 3. Создать заказ | Создан заказ-наряд со статусом WAITING_FOR_SERVICE |
| TC-009 | Получение заказа-наряда | Заказ существует | 1. Указать orderId. 2. Отправить GET-запрос | Система возвращает данные заказа |
| TC-010 | Изменение статуса заказа | Заказ существует | 1. Указать orderId. 2. Передать новый допустимый статус | Статус заказа изменён |
| TC-011 | Создание диагностики | Существует заказ-наряд | 1. Открыть диагностику заказа. 2. Ввести результаты. 3. Сохранить | Результат диагностики сохранён |
| TC-012 | Получение диагностики | Диагностика существует | 1. Указать orderId. 2. Отправить GET-запрос | Система возвращает результаты диагностики |
| TC-013 | Получение списка работ | В системе существуют работы | 1. Отправить GET /works | Система возвращает список доступных работ |
| TC-014 | Добавление работы в заказ | Существует заказ и работа | 1. Указать orderId. 2. Указать workId. 3. Указать количество. 4. Сохранить | Работа добавлена в заказ |
| TC-015 | Получение списка запчастей | В системе существуют запчасти | 1. Отправить GET /parts | Система возвращает список запчастей |
| TC-016 | Получение запчасти | Запчасть существует | 1. Указать partId. 2. Отправить GET-запрос | Система возвращает данные запчасти |
| TC-017 | Проверка наличия запчасти | Запчасть существует | 1. Передать partId. 2. Отправить запрос | Система возвращает информацию о наличии и количестве |
| TC-018 | Завершение обслуживания | Все необходимые работы выполнены | 1. Открыть заказ. 2. Изменить статус на READY_FOR_PICKUP. 3. После выдачи изменить статус на COMPLETED | Заказ получает соответствующий конечный статус |
| TC-019 | Отмена заявки | Существует заявка, допускающая отмену | 1. Открыть заявку. 2. Выполнить отмену | Заявка получает статус CANCELLED |
| TC-020 | Фильтрация заявок по статусу | В системе существуют заявки с разными статусами | 1. Передать параметр status. 2. Выполнить GET /requests | Система возвращает заявки только указанного статуса |

## 3. Проверка HTTP-кодов

| ID | Сценарий | Ожидаемый HTTP-код |
|---|---|---:|
| TC-021 | Успешное получение ресурса | 200 |
| TC-022 | Успешное создание клиента | 201 |
| TC-023 | Успешное создание заявки | 201 |
| TC-024 | Успешное создание заказа | 201 |
| TC-025 | Запрашиваемый ресурс отсутствует | 404 |
| TC-026 | Переданы некорректные данные | 400 |
| TC-027 | Возник конфликт данных | 409 |

---

## 4. Критерии прохождения

Тест считается пройденным, если:

- фактический результат соответствует ожидаемому;
- возвращается предусмотренный HTTP-код;
- созданные объекты получают уникальные идентификаторы;
- статусы объектов изменяются согласно бизнес-правилам;
- система корректно обрабатывает ошибочные запросы.

---

## 5. Итог

Набор тест-кейсов покрывает основные пользовательские сценарии системы:
работу с клиентами и автомобилями, создание заявок, формирование
заказов-нарядов, проведение диагностики, работу с услугами и запчастями,
а также завершение обслуживания.
